# ふたごのリバーシ 〜ミミとなかまたち〜 (v7)

## ⚠ 配置ルール（v7からの変更点・重要）

**ZIPの中身を、リポジトリ直下にそのまま置いてください。フォルダは作りません。**

```
（リポジトリ直下）
index.html
manifest.webmanifest
sw.js
icon-192.png
icon-512.png
apple-touch-icon.png
README.md
```

v6までは `icons/` フォルダを前提にしたパスでしたが、実際のアップロードは
ルート直下（フラット）でした。今回、参照パスをすべてルート直下に合わせています。

## v7 の修正

### 1. アイコンが表示されなかった原因（確定）
`index.html` / `manifest.webmanifest` / `sw.js` はすべて `icons/icon-192.png` を
参照していましたが、実際のファイルはリポジトリ直下にあり、全部 404 でした。

さらに悪いことに、Service Worker の `cache.addAll()` は
**1ファイルでも404だと全体が失敗する**仕様のため、SWのインストール自体が
毎回失敗していました（＝オフライン動作も効いていない状態）。

対策:
- 参照パスをルート直下（`./icon-192.png`）に統一
- `apple-touch-icon` に 180x180 の明示指定を追加（iPhoneのホーム画面用）
- manifest の `purpose` を `any` と `maskable` に分離
  （`"any maskable"` の同時指定はAndroidで余白が潰れることがある）
- SWのキャッシュ登録を1ファイルずつに変更し、1つ欠けても他は生き残るように
- `CACHE_VERSION` を v6 → v7

### 2. ダンジョン終盤で落ちる件
ヘッドレスで全10階 × 3回（計30局）を最後まで通し、
ボタン乱打4,000回も含めてJavaScriptの例外は0件、
DOMノード数・保留タイマー数・ヒープの増加もありませんでした。
つまり**コードの論理エラーではなく、端末側の資源枯渇**である可能性が高いため、
終盤に負荷が集中する箇所を狙って対策しました。

- **効果音**: 終盤は1手で最大18枚めくれ、そのたびにオシレーターを生成していた。
  勝利音・レベルアップ音と重なると同時に25個以上のノードが生きる状態になり、
  iOSではこれがメモリ圧迫→強制終了の典型パターン。
  同時発音を6個までに制限し、鳴り終わったノードを必ず `disconnect` するよう変更。
  めくり音は先頭5枚のみ、アニメ遅延も480msで頭打ちに。
- **読み上げ**: iOSの `speechSynthesis` は短時間に連続呼び出しすると
  ページごと反応しなくなる既知の挙動がある。終盤は解説文が長くなるうえ、
  CPU実況も重なって発話が増えていた。1.1秒の間隔制限・60文字で打ち切り・
  バックグラウンド移行時の `cancel` を追加。CPU実況のうち
  「おける場所が少ない」は終盤では出さないように変更。
- **最後の一手のめくりアニメが消える不具合**も併せて修正
  （`finishGame` が保留中のアニメタイマーを巻き添えで止めていた）。

### 3. 原因追跡のための仕組み
それでも落ちる場合に備え、例外の内容を端末に記録するようにしました。
**メニュー画面の下部に赤い枠でエラー内容が表示されます**（タップで消去）。
落ちたあとにアプリを開き直して、その赤い表示のスクリーンショットを送っていただければ、
原因を特定できます。何も出ていなければ、JavaScriptの例外ではなく
Safariによる強制終了（メモリ）と判断できます。

メニュー右下に `v7` と表示されます。ここが v7 になっていなければ、
まだ古いキャッシュを掴んでいます。

## 更新が iPhone に届かないときは
ホーム画面のアイコンを削除 → Safariで公開URLを開き直す →「ホーム画面に追加」。
（今後 index.html を触ったら、必ず sw.js の CACHE_VERSION を上げてください）
