## 更新が iPhone に届かないときは
Service Worker のキャッシュが古い版を掴んでいます。今回 `CACHE_VERSION` を
`v5 → v6` に上げてあるので、通常は次回起動時に自動で入れ替わります。
それでも古いままなら、ホーム画面のアイコンを削除 → Safariで再アクセス →
「ホーム画面に追加」し直してください。
（今後 index.html を触ったときは、必ず sw.js の CACHE_VERSION を上げること）

## v6 の変更点

### A. 途中で落ちる不具合の修正（本題）
原因は「前の対局で予約した setTimeout が、新しい対局でも生き続けること」でした。
再現できた症状は3つ:

1. CPU思考中にメニューから「ふたりであそぶ」を選ぶと、生き残った cpuPlay が
   `aiConfig = null` に対して実行され TypeError。busy が true のまま固まる。
2. 対局終了直後に新しい対局を始めると、前の結果画面が上にかぶさる。
3. 前の対局のCPUが、新しい盤面に勝手に石を置いて盤が壊れる。

対策:
- 対局ごとに通し番号 `gameId` を振り、古い予約は実行時に破棄（`later()`）
- `startGame` / メニューを開いた時点で予約を全キャンセル
- `cpuPlay` に「CPUのいない対局では動かない」ガード
- `finishGame` の二重実行防止（経験値の二重加算も防止）
- 例外を拾って盤上で固まらせない `recover()` と、8秒進まなければ自動復帰する番人

### B. 動作を約7倍高速化（フリーズ→強制終了の予防）
探索と採点が毎回2次元配列をコピーしていたため、iPhoneでは1手ごとに
秒単位で固まっていました。64マスの Int8Array を置く→戻す方式に変更。
旧実装と 1,080局面 × 深さ2/3/4 で評価値・選択手が完全一致することを確認済みで、
**CPUの強さは一切変わっていません**。（深さ4の最悪値 471ms → 65ms）

### C. iPhone の音まわり
バックグラウンド復帰時に AudioContext を resume。停止中は音を予約しないので、
長時間プレイでメモリが膨らんで落ちる経路も塞いでいます。

### D. ホーせんせいの解説パワーアップ
- 採点を「その局面で選べた手の幅」に対する相対評価に変更
  （従来の固定しきい値 15/40点 は局面によって甘辛が激しかった）
- 判定材料を追加: 角を相手に与えたか / 確定石の増加 / 相手の着手可能数 /
  開放度 / 局面フェーズ（序盤・中盤・終盤）
- CPUの手にも実況（角を取られた、角が空いたチャンス、など要所だけ）
- おしい手のとき、盤上に ★ で「ここが良かったよ」を表示
- ヒントを ◎ ○ △ の3段階に
- 形勢ゲージを常時表示（終盤は石数、それ以前は位置評価で自動切替）
- ホーせんせいの表情差分（にっこり / おどろき / かんがえ中）
- 日本語の読み上げ ON/OFF（🔊ボタン。まだ字が読めなくても遊べる）
- 対局後の「ふりかえり」と「きょうの まなび」
- 「まったなし」で成績とふりかえりも巻き戻るように修正
